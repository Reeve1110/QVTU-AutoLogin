# 门户认证机制分析记录

> 记录 2026-10 对 `http://192.168.120.156` 校园网门户的探测结论，供后续维护参考。

## 1. 系统判定

| 项目 | 结论 | 判定依据 |
|---|---|---|
| 认证厂商 | **锐捷（Ruijie）SAM+ / operator-sam** | 前端 `assets/config.js` 中 footer 为"锐捷网络股份有限公司"；接口 `/eportal/adaptor/*`、`/sam/api/protected/*` |
| Portal 形态 | Angular 单页应用（`/portal/portal-main`） | `app-root` + `main.js` + 懒加载 chunk |
| 登录方式 | **CAS SSO 登录页**（`/cas-sso/login`），嵌入在门户的 iframe 中 | 组件 `app-pc-authenticate` 的 `ssoPath = "/sam-sso/login"`；`window.__PLATFORM_SSO__ = 'cas-sso'` |
| 内核加密开关 | 关闭（`crypto: false`） | `assets/config.js` 与响应头 `encrypted: false` |
| WiFi SSID | `QVTU-2#`（校园网） | `netsh wlan show interfaces` |

访问 `http://192.168.120.156` 的跳转链：

```
GET /                            -> 302 /eportal/redirect.jsp
GET /eportal/redirect.jsp        -> 302 /portal/portal-main?sessionId=...&userIp=...&ssid=QVTU-2%23&nasIp=...&userOnline=...
GET /portal/portal-main          -> 200 门户 SPA
```

## 2. 关键接口（实测）

| 接口 | 说明 |
|---|---|
| `GET /eportal/redirect.jsp` | 返回带 `sessionId / userIp / userMac / ssid / nasIp` 的跳转 |
| `GET /eportal/adaptor/getOnlineUserInfo?sessionId=X` | 在线状态。`data.onlineUser` 非空表示已在线 |
| `POST /eportal/workFlow/getCurrentNode` | 流程引擎节点，body `{"sessionId":"X","flowKey":"portal_auth"}`；已在线时返回 `currentNodePath: "finish"` |
| `POST /eportal/network/userOnline` | 在线确认，body `{"sessionId":"X"}` |
| `GET /eportal/auth/json/getOnlineUserInfo` | 经典 JSON 在线查询（无 sessionId 时返回 `dx.failed.user.offline`） |

> ⚠️ `/api/aggregation/**`（如 `portalAuthen/login`、`flowProcedure/flowIdentityVerify`）在未建立门户会话时会 **302 到 `/login`**，因此不适合作为独立的自动化入口。

## 3. 登录表单（实测结构）

登录页地址：`/sam-sso/login`（会跳到 CAS 登录页），实际表单：

```html
<form id="normalLoginForm" method="POST"
      action="http://192.168.120.156/cas-sso/login?accept-language=zh-CN">

  <input name="username" id="nameInput" type="text" placeholder="请输入账号"/>
  <input type="password" placeholder="请输入密码"/>   <!-- 注意：没有 name 属性 -->

  <input type="hidden" name="type"        value="UsernamePassword"/>
  <input type="hidden" name="_eventId"    value="submit"/>
  <input type="hidden" name="geolocation" value=""/>
  <input type="hidden" name="execution"   value="<login-page-flowkey>"/>
  <input type="hidden" name="captcha_code" value=""/>

  <button id="submitBtn" type="submit">立即登录</button>
</form>
```

**提交时页面 JS 会临时追加三个字段**（`main.js` 中的 `LoginNormalComponent`）：

```js
form.appendChild(<input name="croypto"        value = <#login-croypto 的文本>>);
form.appendChild(<input name="password"       value = AES(<#login-croypto>, 明文密码)>);
form.appendChild(<input name="captcha_payload" value = AES(<#login-croypto>, JSON.stringify(captcha_payload))>);
form.submit();
```

加密算法（`main.js` 内 `Bn.aesEncrypt`）：

```js
static aesEncrypt(keyB64, plain) {
  const key = CryptoJS.enc.Base64.parse(keyB64);
  return CryptoJS.AES.encrypt(plain, key,
         { mode: CryptoJS.mode.ECB, padding: CryptoJS.pad.Pkcs7 }).toString();
}
// 等价于：Base64( AES-128-ECB-PKCS7( key = Base64Decode(croypto), 明文 ) )
```

实测抓到的字段（通过拦截 `HTMLFormElement.prototype.submit` 获得，未真正提交）：

```json
{
  "username": "<学号>",
  "type": "UsernamePassword",
  "_eventId": "submit",
  "geolocation": "",
  "execution": "560458c7-..._ZXlKaGJHY2lPaUpJVXpVeE1pSXN...",
  "captcha_code": "",
  "croypto": "<Base64 密钥>",
  "password": "<AES 密文>"
}
```

成功判定：提交后 `/cas-sso/login` 返回重定向，门户 iframe 拿到 CAS 票据并通知父页面，
父页面继续调用网络认证接口，最终客户端 IP 上线。

## 4. 为什么最终选择"浏览器驱动"而不是直接调接口

1. CAS 登录成功后，门户还要走一段**服务端流程引擎**（`workFlow/getCurrentNode` 节点编排）
   才会真正把客户端上线，这段流程依赖服务端 session 状态，纯 HTTP 复刻成本高、易失效。
2. 门户页面的表单结构（id / 有无 name 属性 / 追加字段）会随厂商版本变化，
   浏览器驱动天然免疫这些变化。
3. 实测已确认可以在真实页面上稳定定位
   `#normalLoginForm input[name=username]`、`input[type=password]`、`#submitBtn`。

## 5. 复现/调试方法

自动登录失败时，程序会把失败现场的各 frame HTML 文本保存到
`我的文档\AutoLogin\logs\fail_<原因>_<时间戳>.html`（纯文本，不含截图）。
结合 `autologin.log` 的运行日志即可定位问题。

## 6. 端到端验证记录

**2026-10-10 21:52 实测：未联网状态下自动登录成功。**

关键点：真正的登录页不是门户内嵌的 `/cas-sso/login`，而是**学校统一身份认证 CAS**
（`https://sid.qvtu.edu.cn/cas/login`），门户只是把它作为 iframe 引进来，因此
`page.frames` 里能定位到的表单 frame URL 形如：

```
https://sid.qvtu.edu.cn/cas/login?service=http%3A%2F%2F192.168.120.156%2Fcas-sso%2Flogin
        %3Fclient_name%3Dsidadapter%26accept-language%3Dzh-CN%26delegatedclientid%3DTST-...
```
