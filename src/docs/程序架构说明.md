# 程序架构说明

> 记录 v26.10.6 的模块划分、线程模型、双状态判定流程与实现要点，供后续维护参考。

## 1. 模块职责

| 模块 | 职责 |
|---|---|
| `gui.py` | tkinter/ttk 界面。三个页签（状态 / 日志 / 设置）+ 托盘接入 + 关闭分支 + 首启/静默启动判定 + `--diag` 自检。设置页分节：账号与门户 / 登录与监听 / 开机自启 / 托盘与关闭行为 / 关于与联系。CLI：`--show / --minimized / --diag / --version / --service-run / --apply-autostart`。**不直接做网络或登录动作**，只调 `Engine`。 |
| `engine.py` | 双状态事件驱动监测引擎。后台线程跑「状态 A 休眠 / 状态 B 监听」状态机，对外暴露 `start/stop/pause/resume/force_login/login_once/status/update_config/set_notify_callback`。 |
| `netevents.py` | 系统网络变更事件监听：ctypes 包一层线程，调 `NotifyAddrChange` / `NotifyRouteChange`，事件到来时回调（唤醒引擎）。状态 A 靠它做到「不轮询也能秒级感知」。 |
| `config.py` | 配置模型与持久化。`DEFAULTS` 是唯一权威结构；深合并实现旧配置自动升级；`save()` 剔除已废弃键；`validate()` 做范围校验；`has_credentials()` 判断是否首次使用。账号密码默认空串。 |
| `logbus.py` | 日志中枢。写文件（**只保留 24 小时**，按行时间戳清理，无体积轮转）+ 内存环形缓冲（供界面刷新）+ 订阅推送（供界面实时追加）+ `clear()`。 |
| `autostart.py` | 开机自启统一入口：**首选 Windows 服务**（`apply_autostart` → `install_service` + `start_service`），失败自动退回计划任务 + 启动文件夹（`register_both`）；管理员权限（检测 + `ShellExecuteW runas` 提权）；**系统残留枚举与一键清理**（`list_system_entries` / `purge_system_entries`）。系统条目统一命名 `QVTUAutoLogin`。 |
| `service.py` | **Windows 服务**（pywin32 `ServiceFramework`）：开机由 SCM 自动拉起（`SERVICE_AUTO_START`，早于用户登录），轮询会话状态，一旦有用户进入桌面（`WTSActive`）就用 `WTSQueryUserToken` + `CreateProcessAsUser` 把 `AutoLogin.exe --minimized` 拉进该用户会话。pywin32 缺模块时整个功能优雅降级（`available()` 为假）。 |
| `singleinstance.py` | 单实例保护：`CreateMutexW` 命名互斥体（`Local\QVTUAutoLogin_SingleInstance`，每个登录会话一把）。抢不到锁时用 `activate_window()` 把已有窗口还原置前，找不到再 `MessageBoxW` 提示。进程退出即释放，无需崩溃清理。 |
| `tray.py` | 托盘图标与菜单（pystray + Pillow），依赖缺失时降级为「不可用」；图标按状态缓存，同一状态只绘制一次。托盘**常驻**，启动/退出/登录结果通知靠它弹出。 |
| `artwork.py` | 图标绘制：蓝底白色 WiFi 符号 + 右下角状态点；同一套图形同时产出窗口 `.ico` 与运行时托盘图标。 |
| `netcheck.py` | `get_wifi_ssid()`（netsh）/ `is_wifi_in_prefix()` / `is_internet_available()`（**多探针并行发起、任一命中即返回**，单次耗时≈单个探针超时；响应特征校验排除门户劫持假联网；记住上次命中探针）/ **WiFi 配置「自动连接」检测与设置**（`profiles_missing_autoconnect` / `set_profile_autoconnect`，拒绝时弹 UAC）。netsh 调用经 `procutil` 隐藏窗口。 |
| `portal_login.py` | 登录引擎。Playwright 驱动真实浏览器填表提交（详见 `门户认证机制分析.md`）；**提交后改为「通了立即返回」的快速确认**（不再固定 `sleep(3)`），轮询间隔压到 0.25~0.4s；失败时把可读原因写进 `last_error`，引擎据此提示用户。**浏览器启动统一走 `launch_channeled()`**（把 `chrome_channel` 展开为「所选 → 另一个 → 内置内核」；`auto` 只是「不指定首选」，**绝不可当作 `channel=` 传给 Playwright**）。 |
| `procutil.py` | 子进程调用工具：`run_hidden()` / `popen_hidden()`，强制 `CREATE_NO_WINDOW` + `SW_HIDE`，让 netsh 等控制台子进程不再闪黑窗。 |
| `paths.py` | 路径解析：`app_dir()`（源码=项目目录 / exe=exe 所在目录）、`data_dir()`（用户数据=文档\AutoLogin）、`resource_dir()`（只读资源）、`is_frozen()`。 |
| `version.py` | 程序名 `APP_NAME`（`AutoLogin`）、标题 `APP_TITLE`、版本号、联系微信、Gitee 地址、**系统条目命名前缀 `SYSTEM_TAG`（`QVTUAutoLogin`）**、互斥体名 `MUTEX_NAME`、**服务名 `SERVICE_NAME`（`QVTUAutoLoginService`）与显示名**的唯一定义处。 |
| `main.py` | 命令行入口，复用 `Engine`；支持 `--once / --force / --gui`。 |
| `build_exe.py` | PyInstaller 打包脚本：生成版本资源、调用 PyInstaller、产出单文件 exe；打包时**排除无用依赖模块并启用 UPX 压缩**，打包后自动发布到项目外 Release 目录。 |

## 2. 线程模型（关键）

```
引擎线程 ──log.add()──► LogBus ──订阅回调──► queue.Queue ──┐
                                                          │（主线程每 200ms 泵出）
主线程 ── root.after(200ms) ── _pump_once() ──────────────┘
       └─ root.after(600ms) ── _status_tick() ──► 差异更新状态面板 / 托盘图标

netevents 监听线程 ──(网络变化)──► threading.Event ──► 引擎 _interruptible_wait 被唤醒
引擎线程 ──(登录成功/失败)──► set_notify_callback ──► _ui_call ──► 主线程弹托盘气泡
主线程 root.after(2500ms) ── _check_update_async() ──► autologin-update 线程 ──► _ui_call(_apply_update_result)
```

要点：
- **绝不在后台线程直接操作 tkinter 控件**。`LogBus` 的回调只做 `queue.put`；
  引擎的通知回调经 `App._ui_call()` → `root.after(0, ...)` 切回主线程。
- 日志泵（200ms）与状态刷新（600ms）**分成两个定时器**：记日志很频繁但不能拖慢界面，
  状态刷新涉及多个 StringVar + 托盘图标，频率低一些更省 CPU。
- 所有 `StringVar.set()` 都经 `_svar()` 做**差异比较**，值没变就不写，避免无谓重绘。
- 托盘菜单回调运行在 pystray 线程，统一经 `App._ui_call()` → `root.after(0, ...)` 切回主线程。
- 引擎的 `_interruptible_wait()` 是整个状态机的心脏：睡觉时被「网络事件 / 手动触发 / 暂停 / 停止」任一唤醒；
  若实际醒来比预定晚 `RESUME_LATE_SEC`(20s) 以上，判定为系统休眠唤醒，醒来后同样校验一次网络。

## 3. 双状态判定流程（engine 主循环）

```
主循环 loop():
  ├─ 取 SSID + 探测外网
  ├─ online  → _state_online()   ── 状态 A【外网已连通】
  └─ ¬online → _state_offline()  ── 状态 B【外网断开】
```

### 状态 A【外网已连通】—— 轻量休眠
```
设置 state=online
循环:
  等到「网络事件 / 心跳(默认60s) / 手动触发 / 暂停 / 停止」之一
  醒来只校验一次外网:
        通  → 继续休眠（若本次是手动触发，提示「外网正常，无需登录」）
        不通 → 进入状态 B（若是手动触发，把「立即登录」诉求转交状态 B 立刻执行，不防抖）
```

### 状态 B【外网断开】—— 核心监听
```
循环（每 offline_poll_sec=2 秒一轮）:
  读 SSID，判断是否校园网（前缀匹配）
  定期探测外网（网络事件 / 手动触发 / 每 3 轮一次）:
        通 → 回状态 A（记录「外网已恢复」）
  ├─ 非校园网     → 不登录，继续监听
  ├─ 冷却期内     → 显示倒计时，等待（手动触发可无视冷却）
  ├─ 防抖未满 2 轮 → 再确认一轮（避免 WiFi 切换瞬断误触发）
  └─ 校园网 + 断网 → 执行登录（先取互斥锁）
            成功 → 回状态 A（弹「已自动登录成功」）
            失败 → 记录 last_error、弹提示、设冷却，冷却结束自动再试
```

- 日志做「情况变化才打印」去重（`_note` / `_note_throttled`），避免每轮刷屏。
- **防重复登录**：`_login_mutex`（`threading.Lock`）保证同一时刻只有一轮登录在跑；
  `_cooldown_until`（单调时间）在整轮失败后生效，冷却期不自动登录。
- 首次进入状态 B 时若还没连上 WiFi 或不是校园网，不会发登录请求（对应「非 QVTU 不登录」）。

## 4. 配置升级

**数据目录**：`config.json` 与 `logs` 都不在程序目录，而是落在 **`paths.data_dir()`**
（=「我的文档\AutoLogin」，可用环境变量 `QVTU_DATA_DIR` 覆盖）。exe 换位置 / 换机器，配置与日志都还在，
也避免装在 Program Files 等只读位置写不进去。老版本放在程序目录的 `config.json`，会在
**打包运行（frozen）**且新位置还没有配置时，由 `config.migrate_legacy_config()` 一次性搬过去
（源码调试不搬，避免误搬开发目录里的模板）。

`config.DEFAULTS` 定义全部键，扁平结构 + 一个 `autostart` 嵌套块，**不含 `triggers` / `exit_rules` /
`check_interval_sec` / `start_minimized`**（这些是旧版遗留，已被 `save()` 的 `_strip_unknown()` 剔除）。
`load()` 用**深合并**把用户文件叠在默认值上，因此：
- 旧版 `config.json` 会被自动补齐新键并丢弃废弃键，无需写迁移代码；
- 用户文件损坏或不是 dict 时回退默认值。

保存用「写 `.tmp` + `os.replace`」原子替换，避免写一半损坏。

**凭据策略**：`DEFAULTS` 与仓库里的 `config.json` 的 `username` / `password` 都是空串，
程序不内置任何账号；界面提供「清空账号密码」按钮，换人使用或借出电脑时一键抹掉。
`has_credentials()` 为假 = 首次使用 → 界面弹窗引导填写；为真 → 静默后台托盘运行。

**关键默认值**：`wifi_prefix=QVTU`、`offline_poll_sec=2`、`online_heartbeat_sec=60`、
`login_cooldown_sec=60`、`autostart={enabled:False, mode:"service", delay_sec:5, run_as_admin:False}`
（**开机自启默认不启用**，由用户主动勾选；启用时首选 Windows 服务）。

## 4.1 日志保留

`logbus.LogBus` 落盘到 `data_dir()/logs/autologin.log`，并**只保留最近 `RETENTION_HOURS`（24）小时**：
`preload()`（启动）时先清一次，运行期间每 `MAINTAIN_INTERVAL_SEC`（600 秒）节流清理一次，
另外文件超过 `max_bytes` 时也顺手清一次。清理按每行 `[YYYY-MM-DD HH:MM:SS]` 时间戳判定，
超期行直接丢弃；没有时间戳的行一律保留（避免误删非本程序写入的内容）；
老版本按体积轮转留下的 `.1` 备份文件一并在清理范围内。

## 5. 开机自启与权限

- **系统条目统一命名 `QVTUAutoLogin`**：Windows 服务名 `QVTUAutoLoginService`、计划任务名、
  启动文件夹快捷方式名、单实例互斥体名都带这个前缀。程序本体仍叫 `AutoLogin`（exe / 标题 / 日志文件）。
- **默认不启用**：`autostart.enabled` 默认为 `False`，新装用户不写任何自启项，由用户在设置里主动勾选。

### 5.0 首选方式：Windows 服务（开机抢先启动）

`service.py` 里是标准 pywin32 服务（`win32serviceutil.ServiceFramework`，服务名 `QVTUAutoLoginService`）：

- **安装**：`service.install()` 用 `CreateService(..., SERVICE_AUTO_START, ...)` 注册为**开机自动启动**
  （非延迟）；已存在则 `ChangeServiceConfig` 更新路径。二进制路径是 `"<exe>" --service-run`。
  注册服务**需要管理员权限**，失败会抛异常，由 `autostart.apply_autostart` 捕获并回退。
- **运行**：`SvcDoRun` 里先 `ReportServiceStatus(SERVICE_RUNNING)`，再启用必要令牌权限
  （`SeAssignPrimaryToken / SeIncreaseQuota / SeTcb`），然后每 `POLL_MS=2000ms` 轮询
  `active_session_ids()`（`WTSEnumerateSessions` 找 `WTSActive` 且 `SessionId>0` 的会话）。
- **把 GUI 拉进用户会话**：`launch_in_session(sid)` 用 `WTSQueryUserToken(sid)` 取该会话用户令牌 →
  `DuplicateTokenEx` 成主令牌 → `CreateEnvironmentBlock` 建用户环境块 → `CreateProcessAsUser`
  以该用户身份启动 `AutoLogin.exe --minimized`；令牌自带 SessionId，子进程自然出现在用户桌面。
- **去重**：服务记住已拉起的会话 id（`self._launched`），同一会话只拉一次；会话注销后从集合中剔除，
  下次登录（哪怕复用同一 id）可再次拉起。
- **兼容性**：pywin32 服务相关模块全部在受保护 `try` 里导入，缺模块时 `available()` 返回假、
  `query_state()` 文本提示「不可用」，整个功能**优雅降级**而不影响界面其它部分；服务侧日志写到
  `<数据目录>\logs\service.log`（界面程序没有控制台），便于真机排查。

### 5.1 备用方式：计划任务 + 启动文件夹

服务装不上时（典型是没拿到管理员权限），`apply_autostart` 自动退回 `register_both()`：
**同时**注册「登录时触发」的计划任务（`delay_sec=0`，最高权限）与启动文件夹快捷方式，互为备份。

- **快捷方式**：`win32com` 的 `WScript.Shell.CreateShortCut`，写到当前用户启动文件夹（无需管理员）。
- **计划任务**：`Schedule.Service` COM，登录触发 + 可选延迟，`Principal.RunLevel=1` 即最高权限。
  **普通权限也能注册**——关键是登录触发器把 `trig.UserId` 设成当前用户（`USERDOMAIN\USERNAME`），
  否则 Task Scheduler 会按「所有用户」处理而报 `E_ACCESSDENIED`；而**最高权限任务需要管理员**。
- **`register_both()`**：两处各自 try/except，某一处失败不影响另一处（错误收集进 `errors`），
  并顺手清理历史旧名条目；返回 `{"task": bool, "startup": bool, "errors": [...]}`。
  **`unregister_both()`** 同时移除两处；**`status()`** 返回 `{"service", "startup", "task"}` 三者是否已生效。

### 5.2 统一入口 `apply_autostart(cfg)`

按 `cfg["autostart"]` 把自启落到系统，并保证**只留一种方式**：

- `enabled=False` → 移除**全部**方式（服务若已装则 `remove()` + `unregister_both()`）；
- `mode="service"`（默认）→ `install_service` + `start_service`；成功后清掉计划任务 / 启动文件夹；
  **失败则回退** `register_both`（把服务错误一并收集），保证用户仍有自启；
- `mode="task"` / `"startup"` → 装对应方式并移除服务。

返回 `{"enabled", "mode", "ok", "errors": [...], "detail": str}`，界面据此提示与刷新状态。
`autostart.apply()` 保留给命令行调用；界面统一走 `apply_autostart`。

### 5.3 一键勾选流程（界面）

界面只保留「开机自启」一个勾选（`_on_auto_toggle`）。勾选即调 `_enable_autostart()`：
先保存设置（`enabled=True, mode=service, run_as_admin=True`），非管理员则
`ShellExecuteW runas` 提权拉起 `gui.py --apply-autostart`；提权实例**在单实例检查之前**处理该参数——
`apply_autostart_cli()` 调 `autostart.apply_autostart()`，把结果写日志并弹一条提示后即退出。
用户当前（普通权限）实例继续在托盘运行，无需整体重启。若用户取消了 UAC 确认，则调
`_rollback_autostart_enabled()` 把勾选与配置一起回滚为关闭。取消勾选则 `_disable_autostart()`（走同一入口）。

### 5.4 清除设置

`list_system_entries()`（只读，供确认展示）与 `purge_system_entries()`（真删）。
只删两类：① 命名属于本程序的条目（`QVTUAutoLoginService` / `QVTUAutoLogin` 及历史旧名
`AutoLogin` / `QVTU_AutoLogin`）；② 名字任意、但目标确实指向本程序 exe / 本项目脚本的条目。
**其它程序的条目一律不碰**，且**不改动 config.json**（只把自启开关同步为关闭）。

## 5.6 单实例、首启与启动/退出通知

- `singleinstance.acquire()` 在 `gui.main()` 里、构造 `App` **之前**调用；抢不到锁就
  `activate_window()`（按标题枚举顶层窗口 → `ShowWindow(SW_SHOW/SW_RESTORE)` + `SetForegroundWindow`）
  唤出已有窗口，实在找不到（例如它在托盘里且窗口被 withdraw）才 `MessageBoxW` 提示一次，然后本进程返回 0。
- 互斥体名 `Local\QVTUAutoLogin_SingleInstance` 是**每会话**一把——同一用户桌面只允许一个实例；
  名字可用环境变量 `QVTU_MUTEX_NAME` 覆盖（`singleinstance.mutex_name()`）——自动化测试用它开独立命名空间，
  免得和用户正在运行的真实实例抢锁。
  退出（含被强杀）时由内核自动释放，不需要额外的清理逻辑。`CreateMutexW` 必须显式设 `restype=c_void_p`，
  否则 64 位下句柄会被截断成 int。
- **首启 vs 静默**：`_want_start_minimized()` = 命令行显式指定优先，否则看 `has_credentials()`：
  没存过账号密码 → 显示主窗口（并切到设置页引导填写）；已存过 → 隐藏到托盘后台。
- **托盘常驻**：`run()` 里无条件 `_ensure_tray()`，因为启动/退出通知依赖它。若托盘不可用，
  最小化启动会退化为显示主界面（至少让用户看得见），并写日志说明。
- 通知时机：`_schedule_start_notice()` 用 `root.after(900, ...)` 等 pystray 注册完图标再弹；
  `_quit_app()` 先把气泡发出去，再 `time.sleep(0.8)` 让 Shell 有时间显示，最后才拆托盘。
  两者都受 `show_notifications` 开关约束，且 `_notify()` 返回「是否真的发出」，没有托盘时不会白白等待。
- **关键操作完成通知**：统一走 `App._notify_result(ok, text)` → `_notify("完成/失败：…")`。
  覆盖保存设置 / 恢复默认 / 清空账号密码 / 开启与关闭开机自启 / WiFi 自动连接 /
  清除设置 / 开始停止监测；登录结果由 `Engine._notify_user()` 在 `_login_round` 里统一发。
  全部受同一开关约束，窗口在前台时也照常发出（正是「完成 / 失败都要提示」的要求）。
- **启动时 WiFi 自动连接检测**：`_check_wifi_autoconnect_async()` 后台线程跑一次
  `netcheck.profiles_missing_autoconnect()`，发现未开启「自动连接」就只弹托盘气泡提醒（不打断使用），
  用户可到设置页一键开启（`set_profile_autoconnect`，需要时弹 UAC）。

## 6. 打包与路径（frozen）

PyInstaller 会把代码解压到 `%TEMP%\_MEIxxxx` 再执行，所以：
- 用 `paths.data_dir()` 定位 `config.json` / `logs`（=「我的文档\AutoLogin」，**绝不落在临时目录**，
  也不随 exe 位置漂移）；用 `paths.app_dir()` 定位 exe 自身与工作目录；
- 用 `paths.resource_dir()` 定位只读资源（`assets/app.ico`）；
- `autostart.launch_command()` 在 `is_frozen()` 时返回 exe 自身，快捷方式/计划任务直接指向 exe；
- 打包参数：`--onefile --windowed --icon --version-file --collect-all playwright --hidden-import pystray._win32`，
  这正是「没有控制台黑窗」和「playwright 驱动（含 node.exe）能正常工作」的关键。
- 自检入口 `gui.py --diag [输出路径]` 会把依赖、驱动、浏览器能否拉起、网络状态写成 JSON，
  界面程序没有控制台，用文件回报最适合。

## 7. 性能取舍

| 措施 | 原因 |
|---|---|
| 状态 A 不轮询，只挂系统网络事件 + 心跳 | 外网正常时常驻也几乎不占 CPU |
| 设置页惰性构建（首次切到该页才创建控件） | 设置页控件最多，是最主要的启动耗时 |
| 状态差异更新 + 日志/状态双定时器 | 避免每次 tick 触发整片重绘 |
| 托盘图标按状态缓存（3 个状态各画一次） | Pillow 绘制 + 转 HICON 开销不小，界面会频繁调用 |
| 日志控件限行 + 首屏只渲染末尾 800 行 | 一次 `insert` 上千行会让界面明显卡顿 |
| 网络探针记住上次命中的 URL | 校园网下不同探针快慢差异很大 |
| **联网检测全部移到后台线程**（`_OnlineWatcher`），登录主链路零阻塞 | 旧实现把探针塞进等待循环，每轮白等 `timeout+0.35s`，「定位表单」要 4~6 秒 |
| **提交后快速确认 + 兜底校验 60→12 秒** | 门户误报成功时会在这里干等，旧值 60 秒是「登录卡十几秒到一分钟」的元凶 |
| **启动监测时后台预热 Playwright** | 首次登录省掉约 1 秒的模块导入 |
| **`Engine.stop()` 默认不 join** | 点「停止监测」立即返回、不阻塞界面；线程在下一个等待边界（≤0.25s）自行退出 |
| `tray` / `playwright` / `netevents` 惰性导入 | PIL + pystray + playwright 的导入会拖慢启动，且非必需路径用不到 |

## 8. 环境要点（踩过的坑）

1. **界面版必须用带 tkinter 的 Python**。WorkBuddy 受管 Python 不含 tkinter；
   `venv` 的 tkinter 可用性**继承自基座解释器**，所以必须用系统 Python（本机 `D:\tool\Python\Python314`）建 `.venv`。
2. **venv 的 `pythonw.exe` 是启动器**：它会再拉起一个真正的解释器子进程，
   窗口归属的 PID 与 `Popen` 返回的 PID **不同**。做进程级测试时要用「启动前后进程差集」识别，
   否则会误判失败、并在清理时漏杀子进程。**onefile 的 exe 同理**（bootloader + 子进程）。
3. **pystray 的 `Icon.stop()` 会阻塞**（win32 后端）：放到 daemon 线程里执行，主流程只放弃引用；
   程序收尾用 `os._exit(0)`，否则托盘的消息循环线程会让进程不退出。
4. **同一个容器里不要混用 `pack` 和 `grid`**：设置页各分节都用 `grid` 排 `_row`，
   末尾若用 `pack` 放提示 Label 会直接抛 `TclError`（已修）。
5. **中文按钮不要写死 `width`**（`width` 单位是平均字符宽，中文约为 2 单位，会被截断）。
6. **高 DPI 屏**：必须在 `tk.Tk()` **之前**调用 DPI 感知，否则界面模糊、控件被裁切。
7. **控制台黑窗（两处，缺一不可）**：
   ① 主进程——exe 用 `--windowed`；源码用 `pythonw` + 启动脚本 `windowstyle=0`（VBS），再加主动 `ShowWindow(GetConsoleWindow(), SW_HIDE)` 兜底；
   ② **子进程**——GUI 进程调用 `netsh` 这类控制台程序时，Windows 会为它新建控制台窗口并闪一下。
      必须统一走 `procutil.run_hidden()`（`CREATE_NO_WINDOW` + `STARTF_USESHOWWINDOW/SW_HIDE`）。
8. **静默启动要在 `Tk()` 之后立刻 `withdraw()`**：如果等托盘建好再隐藏，托盘初始化慢的时候
   主窗口会明显闪一下（测试里表现为「最小化启动却检测到可见窗口」）。
9. **`pack` 顺序决定边框位置**：页脚用 `side="bottom"`，必须**在 Notebook 之前** pack，
   否则 Notebook 的 `expand=True` 会把整块空间吃掉，页脚被挤到窗口外（看不到了）。
10. **单实例互斥体的两个坑**：`CreateMutexW` 的 `restype` 不设为 `c_void_p` 会在 64 位下截断句柄；
    另外「已存在」是靠 `GetLastError()==ERROR_ALREADY_EXISTS(183)` 判断，必须用 `WinDLL(use_last_error=True)`。
11. **计划任务普通权限注册失败（`E_ACCESSDENIED`）**：根因是登录触发器没设 `UserId`，
    Task Scheduler 按「所有用户」处理而拒绝访问。设为 `USERDOMAIN\USERNAME` 即可。
12. **netsh 输出编码**：本机开了「UTF-8 全球语言支持」时 `netsh` 输出是 UTF-8，默认中文系统是 GBK。
    `netcheck._decode()` **先试 UTF-8**、失败再退 GBK——反过来（先 GBK）会把 UTF-8 解成乱码（GBK 几乎什么都能解）。
13. **引擎读取门户对象要容错**：`last_error` 用 `getattr(portal, "last_error", "")` 取，
    否则替换/测试用的门户实现缺这个属性会抛 `AttributeError`，被当成登录失败。
14. **编辑工具偶发「静默丢弃」**：改完关键方法（如 `_create_vars`）要 `grep` 确认改动真的落盘。
15. **登录慢的主因是「串行探针 + 固定等待」**：旧版 `is_internet_available` 逐个探针串行，
    校园网里被墙的探针各挂满 timeout，最坏 `探针数 × 超时`；再叠加提交后固定 `sleep(3)`、
    断网防抖按「2 轮 ×2s」计，累计就是十几秒。改并行探针 + 快速确认 + 按持续时间防抖后显著下降。
16. **并行探针要用「守护线程 + Event」，别用 `ThreadPoolExecutor` 的 `with`**：
    `with` 退出时会 `shutdown(wait=True)` 等最慢的线程，等于退回串行；守护线程 + `Event.wait(超时)`
    才能真正做到「任一命中立即返回、整体不超过超时」。
17. **Windows 服务的「会话拉起」线下无法通过重启验证**：服务能在本机注册 / 启动 / 查询状态，
    但 `CreateProcessAsUser` 把程序真正拉进用户桌面这一步，不重启机器就无法确认。因此 `service.py`
    刻意写得保守——每一步单独 try/except、日志落到 `<数据目录>\logs\service.log`，真机出问题先看它。
18. **不内置在线更新（v26.10.6 起移除）**：早期版本做过「只检查、不自动替换」的在线更新，但即便
    只做检查，也要多维护一份版本清单、多一次启动网络请求，收益有限。v26.10.6 起**整块删除**——
    程序不再发起任何更新相关请求，用户需要新版时到 Gitee 项目页手动下载覆盖即可。

## 9. 源码包与打包

本目录是**精简源码包**，只保留运行与打包所需的文件：

- **源码**：`gui.py` / `main.py` / `engine.py` / `portal_login.py` / `netcheck.py` 等全部 `.py`；
- **打包**：`build_exe.py`（PyInstaller）、`tools/make_icon.py`（生成 `assets/app.ico`）、
  `tools/upx/upx.exe`（压缩器）、`requirements.txt`；
- **模板与文档**：`config.json`（空模板）、`assets/app.ico`、`docs/`。

打包命令：`.\.venv\Scripts\python.exe build_exe.py` → 产出 `dist\AutoLogin.exe`（单文件，约 42MB），
并自动复制到项目外的 Release 目录。打包时**排除无用依赖**（PIL 的 AVIF/WebP 插件、playwright 的
`driver/package/types` 与 `.d.ts`）并启用 **UPX** 压缩。

> 原 `tests/` 自动化测试套件、各类 `.bat` / `.ps1` / `.vbs` 辅助脚本、
> 一次性诊断脚本与界面截图已在本版本移除——它们不参与运行与打包。
> 运行期数据（`config.json` / `logs\`）仍在用户「文档\AutoLogin」，不随源码包分发。
