# AutoLogin 校园网自动登录 v26.10.5

开机或连上校园网（WiFi 名称以 **`QVTU`** 开头，可在设置里改前缀）后自动完成 Portal 认证，
不用再手动开浏览器输账号密码。程序常驻托盘后台，**外网一断就自动重登**。
**单次登录约 7–12 秒。**

> （版本号、微信号、Gitee 地址都在「设置 → 关于与联系」里，可一键复制 / 打开）

## 零、下载与数据位置（先看这里）

- **直接下载发行版 `AutoLogin.exe`**（Gitee 仓库里那个 exe 就是完整程序，**无需解压、无需装 Python**），
  双击即可运行。
- 程序**不会**在 exe 旁边乱放文件。配置与日志统一放在你的**「文档」文件夹**：

  ```
  我的文档\AutoLogin\
  ├─ config.json      ← 你的设置与账号密码（只在本机、明文）
  └─ logs\
     ├─ autologin.log ← 运行日志（纯文本；只保留最近 24 小时）
     └─ diag.json     ← 自检报告（运行 --diag 时生成）
  ```

  日志与失败现场一律为**纯文本**（不生成任何截图）；登录失败时的页面快照也以文本
  （`fail_*.html`）形式保存在同一 `logs\` 目录下。

  所以**挪动 exe、换电脑都不影响**：只要「文档\AutoLogin」还在，配置就还在。
  老版本把配置放在 exe 旁边的，升级后第一次运行会**自动迁移**过来。

## 一、两种启动方式

| 方式 | 做法 | 适合 |
|---|---|---|
| **单文件 exe** | 双击 `dist\AutoLogin.exe` | 拷到任何电脑直接用，不用装 Python |
| **源码运行** | `.\.venv\Scripts\python.exe gui.py` | 改代码 / 看日志方便 |

两种都**在后台运行，不弹黑色命令行窗口**。程序自身（exe / pythonw）不会有控制台，
连 `netsh` 这类内部调用的控制台子进程也已禁用窗口，**运行期间不会再闪黑窗**。

## 二、第一次用 & 之后怎么跑

**首次启动（还没存过账号密码）**：弹出主窗口并自动切到「设置」页，引导你填账号密码、保存。

**之后每次启动**：直接隐藏主窗口，安静驻留在系统托盘后台运行；双击托盘图标可唤出主界面。

**开机自启**：**默认不启用**，需要时在「设置 → 开机自启」勾选「开机自启」即可。勾选后会自动弹一次
UAC 授权框（获取管理员权限），随后把程序注册为 **Windows 服务**（**开机抢先启动**：服务先于任何
用户登录就绪，你一进桌面就立刻把托盘程序拉起），并在下方只读显示服务状态。万一服务注册不上
（例如未取得管理员权限），会**自动退回**「计划任务 + 启动文件夹」两种备用方式，保证仍有自启。
不想自启时取消勾选，会把服务与备用条目一起移除。

## 三、界面能做什么

| 需求 | 在界面哪里 |
|---|---|
| 可视化界面 + 实时日志 | 「状态」页（当前 WiFi / 是否校园网 / 外网状态 / 运行状态 / 上次登录 / 倒计时 + 最近日志预览）、「日志」页 |
| 日志清除 | 「日志」页 → **清除日志**（同时清空日志文件）；另有 保存日志 / 刷新 / 级别过滤 / 自动滚动 |

| 清除设置 | 「设置 → 清除设置」：删除 Windows 服务 / 任务计划程序 / 启动文件夹里**本程序（QVTUAutoLogin）**留下的条目，**不影响其它任何程序**，也**不改动你的配置与账号密码** |
| 恢复默认 | 「设置 → 恢复默认」：把 config.json 全部恢复为默认值（**账号密码也会清空**） |
| 退出时：退出 / 隐藏至托盘 | 关闭窗口时可选隐藏到托盘或退出；可勾「关闭时弹窗询问」并记住选择 |
| 启动 / 退出有提示 | 程序启动和退出时各弹一次托盘气泡通知（可在「托盘与关闭行为」里关掉）；登录成功 / 失败也会弹一次 |
| 不会重复运行 | 同一时间只允许一个实例；重复双击不会开出第二个，而是把已有窗口叫到前台 |
| 不会重复自启 | 勾选开机自启会把程序注册为 Windows 服务（备用为计划任务 + 启动文件夹），三种方式**只保留一种**；取消勾选、或点「清除设置」会把它们一起清掉，历史遗留项也自动清理 |
| 联系方式 | 「设置 → 关于与联系」，含版本号、微信号、Gitee 项目地址，均可一键复制 / 打开 |

## 四、核心机制：双状态事件驱动

程序常驻后台，只有两种状态，靠**系统网络变更事件**和**心跳**在两者间切换：

### 状态 A【外网已连通】—— 轻量休眠
- **不轮询、不检测 WiFi、不登录**，几乎不占资源。
- 只挂两类唤醒源：
  1. **系统网络变更事件**（网卡 / WiFi 连接、断开、切换）—— 监听系统消息，秒级唤醒；
  2. **心跳**（默认每 60 秒一次）—— 兜住「校园网认证过期不会产生任何网络事件」的情况。
- 醒来只**快速校验一次外网**：通 → 继续休眠；不通 → 进入状态 B。
- 若实际醒来时间比预定晚 20 秒以上，判定为**休眠唤醒**，同样触发一次校验。

### 状态 B【外网断开】—— 核心监听
- **每 2 秒检测一次当前 WiFi 名称**：
  - 以设定前缀（默认 `QVTU`）开头 → 连续确认后**自动登录**；成功 → 回到状态 A（并弹托盘提示）；
    失败 → 记录原因、弹托盘提示，进入**冷却**，冷却结束自动再试；
  - 不是校园网 → **不登录**，继续监听；期间定期探测外网，捕捉「手动认证成功 / 切到其它能上网的网络」→ 回到状态 A。

### 网络切换 / 休眠唤醒也能感知（对应需求 1.4）
| 情况 | 处理 |
|---|---|
| 笔记本休眠再唤醒 | 用单调时钟跳变检测到「醒来晚了」，立即校验外网 |
| WiFi 从别的网络切到 QVTU | 系统网络事件唤醒 → 进入状态 B → 检测到校园网 → 登录 |
| QVTU 已连但认证过期、外网断 | 心跳到点校验发现断网 → 进入状态 B → 自动重登 |

### 防重复登录（对应需求 1.6）
- 登录全程持有**互斥锁**：正在登录时，任何新的自动或手动登录请求直接被拒绝，绝不并发提交。
- 一整轮（含重试）失败后设置**冷却时间**（默认 60 秒），冷却期内不再发起自动登录，
  避免短时间大量提交被校园网限流或锁号。手动点「立即登录」可无视冷却。

### 程序退出后
不再做任何检测；下次开机自启（或手动启动）才重新开始。

### 判定「真的联网」
未认证时门户会把请求劫持并返回 200（假联网），所以程序**强制不走代理**，并校验响应特征
（如 `msftconnecttest` 必须返回含 "Microsoft Connect Test"），多探针任一命中才算联网。
**多个探针并行发起、哪个先通就用哪个**（整体耗时约等于单个探针超时，而不是「探针数 × 超时」），
命中的探针会被记住、下次优先生效，进一步省探测时间。

## 五、托盘、命名与自启项

- 托盘图标是**蓝底白色 WiFi 符号 + 右下角状态点**：🟢 已联网、🟠 未联网、⚪ 未监测。
- 托盘菜单：显示主界面（双击图标也行）、立即登录、开始 / 暂停监测、退出程序。
- 程序**启动后**弹一次「程序已启动」通知，**退出时**再弹一次「程序已退出」；
  **关键操作**（保存设置 / 恢复默认 / 清空账号密码 / 开启与关闭开机自启 / WiFi 自动连接 /
  清除设置 / 登录成功失败）在完成时也会各弹一条，并明确标出「完成」或「失败」。
  不想看这些提示，可在「设置 → 托盘与关闭行为」取消「显示托盘气泡通知」。

### 程序名 vs 系统条目名
- **程序本体叫 `AutoLogin`**（exe / 窗口标题 / 日志文件名）。
- **系统里留下的条目统一叫 `QVTUAutoLogin`**：Windows 服务名、计划任务名、启动文件夹快捷方式名、
  单实例互斥体名都带这个前缀，方便你在「服务 / 任务计划程序」里一眼认出、也方便一键清理。
- 勾选「开机自启」时**首选注册 Windows 服务**（开机抢先启动：服务先于用户登录就绪，进入桌面即拉起
  托盘程序）；服务装不上会自动退回「计划任务 + 启动文件夹」。三种方式**只保留一种**，
  旧版本用过的名字（`AutoLogin` / `QVTU_AutoLogin`）升级时会被**自动清理**。
- 只有 `wifi_prefix`（默认 `QVTU`）是**功能性**的——那是学校真实 WiFi 名称的前缀，
  改掉就识别不出校园网；可在「设置 → 账号与门户」按需修改。

### 清除设置
「设置 → 清除设置」会先列出将删除的条目让你确认，再删除：
- ① 名字属于本程序的条目（Windows 服务 `QVTUAutoLoginService`、计划任务 / 快捷方式 `QVTUAutoLogin` 及历史旧名）；
- ② 无论叫什么名字、但目标确实指向本程序 exe / 本项目脚本的条目。

**其它任何程序的快捷方式与计划任务都不会碰**，也**不改动 config.json 里的设置与账号密码**。
删除后会把配置里的自启开关同步为关闭（因为系统条目已不存在）。

## 六、命令行与诊断

```powershell
.\.venv\Scripts\python.exe main.py            # 命令行常驻监测（Ctrl+C 退出）
.\.venv\Scripts\python.exe main.py --once     # 只检测一次并打印网络状态
.\.venv\Scripts\python.exe main.py --force    # 立即同步登录一次
.\.venv\Scripts\python.exe main.py --gui      # 打开界面
.\.venv\Scripts\python.exe gui.py --diag      # 自检：依赖/浏览器/网络 → 文档\AutoLogin\logs\diag.json
.\.venv\Scripts\python.exe gui.py --version        # 打印版本号
```

界面还支持 `gui.py --show`（强制显示窗口）/ `--minimized`（强制只留托盘）。

打包 exe：

```powershell
.\.venv\Scripts\python.exe build_exe.py              # 单文件 exe → dist\AutoLogin.exe
.\.venv\Scripts\python.exe build_exe.py --onedir     # 目录版（启动更快）
.\.venv\Scripts\python.exe build_exe.py --no-publish # 只出 dist\，不复制到 Release
```

打包完成后会**自动**把产物复制到项目外的 Release 文件夹 `D:\Desktop\QVTU-AutoLogin-release\`，
并**按版本号命名**留一份历史副本（同时保留固定名供 Gitee 仓库引用）：

- `AutoLogin.exe` —— 固定名（Gitee 仓库里就是这一份）
- `AutoLogin_v<版本号>.exe` —— 版本号命名副本（本地历史留存，不进仓库）

Release 目录可用环境变量 `QVTU_RELEASE_DIR` 覆盖。

## 七、目录结构

```

├─ gui.py                  可视化界面（状态 / 日志 / 设置）

├─ logbus.py               日志中枢（文件 + 内存缓冲 + 订阅推送 + 清除 + 24 小时保留）
├─ autostart.py            开机自启（Windows 服务 / 计划任务 / 启动文件夹）、管理员权限、系统残留清理
├─ service.py              Windows 服务（开机抢先启动，把托盘程序拉进用户会话）
├─ singleinstance.py       单实例保护（命名互斥体，重复启动唤出已有窗口）

├─ artwork.py              图标绘制（窗口 ico 与托盘图标同一套图形）
├─ netcheck.py             WiFi SSID / 真联网判定 / WiFi 自动连接检测与设置
├─ portal_login.py         登录引擎（Playwright 驱动真实浏览器）
├─ procutil.py             子进程调用工具（强制不弹控制台黑窗）
├─ paths.py                路径解析（app_dir=程序目录；data_dir=文档\AutoLogin）
├─ version.py              版本号、标题、联系微信、Gitee 地址、系统条目命名前缀
├─ config.json             配置模板（**账号密码默认为空**，由你填写）
├─ requirements.txt        依赖清单
├─ assets/app.ico          程序图标
├─ build_exe.py            打包脚本（PyInstaller，内嵌版本号；打包后自动按版本号复制到 Release 文件夹）
├─ dist/                   打包产物
├─ tools/                  打包辅助（make_icon.py 生成图标、upx/ 压缩器）
├─ docs/                   认证机制分析、架构说明
└─ .venv/                  本地虚拟环境（不随源码分发）
```

> 运行期数据**不放在项目目录**：`config.json` 与 `logs\` 都在「我的文档\AutoLogin」
> （见第零节）。项目里的 `config.json` 只是随包分发的**空模板**。

## 九、性能说明

- 状态 A（外网正常）下**不轮询**，只在系统网络事件 / 心跳时醒一次，CPU 占用接近 0。
- 设置页**首次切换时才构建**，启动更快。
- 状态面板只在数值真的变化时才刷新，托盘图标同一状态只绘制一次并缓存。
- 日志控件限制保留行数（超出自动裁掉前半），首屏只渲染末尾若干行。
- 网络探针会记住上次成功的那个 URL，优先复用。
- `--onefile` 的 exe 每次启动需要先把内容解压到临时目录（约 60MB），冷启动会比源码版慢几秒；对启动速度敏感可以用 `build_exe.py --onedir`。

## 十、常见问题

| 现象 | 处理 |
|---|---|
| 双击 `dist\AutoLogin.exe` 没反应 | 用源码运行的话需自备 Python 环境（`.\.venv\Scripts\python.exe gui.py`）；exe 版不依赖 Python |
| 首次启动一直弹窗 | 正常：还没存过账号密码，填写并保存后，之后启动就会静默进托盘 |
| 界面提示「尚未设置账号密码」 | 「设置 → 账号与门户」填写并保存 |
| 日志出现「登录页要求填写验证码」 | 学校启用了风控验证码，需手动登录一次或降低登录频率 |
| 日志出现「认证返回错误信息」 | 账号/密码不对或账号被锁，检查「设置 → 账号与门户」 |
| 一直「未能在页面上找到登录表单」 | 到「日志」页看失败原因；程序会把失败现场的各 frame HTML 文本存到「文档\AutoLogin\logs」下（`fail_*.html`） |
| 勾了「开机自启」但提示没权限 | 勾选后会自动弹一次 UAC 授权框，点「是」即可；若点了「否」，勾选会自动回滚，重新勾选再来一次 |
| 开机后没自启 | 「设置 → 开机自启」看「Windows 服务 / 计划任务 / 启动文件夹」三项里的状态；正常应显示「Windows 服务」已启用。若服务那条显示异常，取消勾选再重新勾选一次即可（会先尝试服务，失败自动用计划任务 + 启动文件夹兜底） |
| 想彻底清掉自启痕迹 | 点「设置 → 清除设置」 |
| 提示有新版本但不知道去哪更新 | 程序不再自带更新检查；有新版本请到「设置 → 关于与联系」里的 Gitee 项目地址点「打开链接」，下载最新 `AutoLogin.exe` 覆盖旧文件即可 |
| 双击图标没反应 / 又开了一个 | 程序只允许一个实例：已在运行则重复双击会把已有窗口叫到前台；已在托盘时不会另开窗口 |
| 想让「启动文件夹」和「计划任务」只留一种 | 不需要操心——勾选开机自启会**优先用 Windows 服务**，服务装不上才自动退回「计划任务 + 启动文件夹」，三种方式**只会存在一种**；要清就取消勾选或点「清除设置」 |
| 配置被改乱了 | 点「设置 → 恢复默认」全部恢复默认值（注意会清空账号密码） |
| 运行中偶尔闪一下黑窗 | 请用 `dist\AutoLogin.exe` 启动；程序内部调用（netsh 等）已全部禁用窗口，不会闪 |
| 外网明明连着却一直重登 | 检查探针 URL 是否被校园网劫持；可在日志里看每次「外网校验」结果 |

## 十一、注意事项

- 仓库与打包产物里的 `config.json` **不含任何账号密码**；你填写的凭据只保存在本机的
  **「文档\AutoLogin\config.json」**里（明文），请不要把该文件上传到公开仓库或分享给他人。
  界面提供「清空账号密码」按钮。
- 配置与日志放在「文档\AutoLogin」（不再紧挨着 exe）；运行日志**只保留最近 24 小时**，自动清理。
- 程序只在本机运行、只访问校园网门户，不向任何第三方发送数据。
- 若学校启用了「登录风控 / 验证码」，自动登录会受限，此时建议保留手动登录。

**登录与稳定性（上一轮）**

1. **修复登录「假成功」与久等（核心 bug）**：新版门户是 Angular 页面，密码框已**没有 `name` 属性**，
   旧代码用 `input[name=password]` 判断「表单还在不在」→ 永远判为成功 → 再空等 60 秒联网校验，
   于是登录看起来要 15~57 秒。现在改为**「确实离开登录页」且「表单确实消失」**（或后台探针确认真的联网）
   才算成功，并在 12 秒内给出结论。
2. **压缩登录耗时**：联网检测移到后台线程（主链路零阻塞）、提交后快速确认、兜底校验 60→12 秒、
   启动时后台预热 Playwright。定位表单从 4~6 秒降到约 0.3 秒。
3. **修复 / 加固 Chrome 登录**：浏览器通道按「所选 → 另一个 → 内置内核」自动回退并记录实际使用的浏览器；
   启动参数加 `--no-proxy-server`，避免系统代理残留导致门户都打不开；设置里新增「自动」通道选项。
4. **一键完成开机自启**：勾选「开机自启」即自动请求一次 UAC，由**提权后的实例**把「最高权限计划任务 + 启动文件夹」一起写好
   （普通权限直接注册最高权限任务会被系统拒绝），写完即退出，主界面继续在托盘运行。
5. **停止监测不再卡顿**：`Engine.stop()` 默认**不做 join**，点击「停止监测」立即返回，
   后台线程在下一个等待边界（≤0.25 秒）自行结束；如需同步等待可显式传超时。
6. **风控友好**：一旦页面出现图形验证码即**立即失败、不再重试**（反复提交会加重风控），并提示用户手动登录一次。
